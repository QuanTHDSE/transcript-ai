# Implementation phases

## Template-to-recording mapping

- Added version-bound mapping batches and per-recording student/question confirmation. Template paragraph IDs identify candidate questions; part and question are validated against the selected template, and preset/template version mismatches are rejected. Filename and transcript hints remain suggestions; only confirmed mappings with completed transcripts and audio analysis expose aligned data. Since transcripts are job-owned in the MVP, `transcript_id` is the transcription job ID.
- `/mapping` creates or reopens a batch, uploads recordings through the existing transcription API, assigns each student/question separately, lists missing confirmed questions per assigned student, and shows analysis status. Scheduler queues audio preparation after confirmation and transcription completion. Explicit prepare allows retries after a reported failure.
- FFprobe records container duration; CPU VAD estimates first/last speech, voiced duration and internal pauses. The batch selects which metric the preset's inclusive duration limits apply to. Speech-based results are explicitly uncertain because VAD boundaries are uncalibrated; silence or missing rules yield `NOT_ASSESSED`.
- Verification: six PostgreSQL-backed tests passed for multiple students, invalid and ambiguous mappings, missing questions, scheduler queueing, mocked duration grading and real JFK audio/VAD. Fresh SQLite migration and frontend TypeScript/build checks passed. Compose restarted on revision `007_recording_mapping`; collection API and `/mapping` returned HTTP 200. Real browser upload-to-mapping and worker interruption recovery for mapping analysis remain unverified; queued/processing analysis may require operational recovery after interruption.

## Custom speaking grading rules

- Added reviewed, immutable grading preset versions linked to a specific template version; assessment requests can record the selected rule version. Original instructions, parsed configuration and persisted duration results are separate records. Existing assessments keep a null rule reference.
- `/grading-rules` supports Vietnamese/English instructions, review and JSON editing, preset versions, optional example limits, required structures, correction styles, red-text protection and duration checks. The conservative parser recognizes limited explicit phrases and always requires human review; unsupported or ambiguous instructions must be added manually.
- `POST /api/v1/grading-presets/parse`, preset/version create/list/detail, and versioned duration-result create/detail endpoints provide the rules workflow. Duration checks use inclusive configured boundaries and return `NOT_ASSESSED` without a rule. Rules are recorded on assessments; automatic application to the existing transcription/feedback pipeline and document export is not yet implemented.
- Verification: targeted tests cover bilingual parsing, explicit review, version isolation, persistence, assessment linkage and every example duration boundary on PostgreSQL; fresh SQLite migration and frontend TypeScript/build checks are included in the task handoff.

### Reliable background batch queue

- Implemented: persisted `QUEUED`, `PROCESSING`, `COMPLETED`, `FAILED`, `CANCELED`; independent upload/task delivery; actual validation/extraction/transcription stages; history/detail polling; failed-job retry; safe cancellation; schema migration.
- PostgreSQL owns retry scheduling. Celery Beat sends a recovery task every 30 seconds. Committed queued jobs survive a broker publish failure and are republished; messages expire after 90 seconds, and database claims reject duplicates.
- Transient connection/timeouts and retryable HTTP responses receive exponential delays (10s, 20s, capped at 300s) and at most `JOB_MAX_ATTEMPTS` total attempts (default 3). Invalid media, missing files, permanent model errors, and caught resource errors fail without automatic retry. Hard-killed attempts, including container OOM, follow bounded interruption recovery. Manual retry resets the attempt budget only for failed jobs.
- Atomic claims and per-attempt tokens fence stale writes. Interrupted processing leases expire at `JOB_TIME_LIMIT + 60s`; the worker enforces a hard task limit, then recovery requeues or fails exhausted jobs. Keep the same time-limit configuration on worker and scheduler. Recovery needs Redis, PostgreSQL, the scheduler, and a running worker; startup health checks gate schema readiness.
- Cancellation immediately persists `CANCELED`; queued deliveries become no-ops and active jobs stop at the next stage or discard final output. It does not force-kill native inference. No numerical transcription progress is reported.
- Defaults: one worker process, two inference threads, tiny multilingual CPU/int8 model, 2 CPU cores and 2 GiB container memory; no GPU allocation. Set `WORKER_CONCURRENCY` in `.env`, adjusting memory/CPU limits for the additional cached model copies. Model weights persist in a shared Docker volume; each process reuses its loaded model.
- Start: copy `.env.example` to `.env` (adjust credentials), then `docker compose up --build -d`. API runs `alembic upgrade head` before accepting traffic. `/api/jobs` accepts multipart files and language; `/api/v1/transcriptions/upload` is an upload alias. `GET /api/jobs`, `GET /api/jobs/{id}`, `POST /api/jobs/{id}/retry`, and `POST /api/jobs/{id}/cancel` are live routes. Media content validation runs asynchronously; unsupported extensions/oversized files fail during upload.
- Verification so far: 13 tests pass, one optional real-audio test skipped; frontend TypeScript and production build pass; Compose configuration validates. Dependency installation reports existing Next.js vulnerabilities; dependency remediation remains separate work.
- Runtime verification: PostgreSQL and Redis containers started healthy (`SELECT version()` and `PING` succeeded). Full backend image build was stopped during slow dependency downloads; live Celery execution, PostgreSQL queue tests, and real-model inference remain unverified. Run the documented checks after the image builds; no successful live transcription is claimed.

#### Evidence-based audio analysis

- Added CPU `app.speaking_audio:create_evaluator` as the default AUDIO provider; set `SPEAKING_AUDIO_PROVIDER` to another trusted factory to override it or explicitly blank to disable it. Reuses faster-whisper 1.2.1's bundled cached Silero VAD v6 ONNX model; no new model/package downloads or GPU requirement. Configuration: `SPEAKING_AUDIO_MAX_SECONDS=600` (1–3600), `SPEAKING_VAD_THRESHOLD=0.5`, `SPEAKING_LONG_PAUSE_MS=1500` (300–30000), existing `MEDIA_TIMEOUT_SECONDS`. FFprobe checks media and FFmpeg produces bounded mono 16 kHz PCM in an automatically cleaned temporary directory. Overlong recordings fail rather than being silently truncated.
- Revision `004_audio_analysis` gives criteria unique `(assessment_id, code, source)` identities, keeping transcript fluency and audio fluency distinct. Stores measured intervals/durations/rate/capabilities in `analysis`, explicit per-criterion `NOT_ASSESSED`, and per-finding `uncertain`. Legacy assessments receive an unassessed audio-fluency row for manual retry. Providers that previously returned pronunciation alone remain compatible, with unsupported audio fluency added explicitly.
- Supported: measured VAD speech/non-speech intervals, speech duration, internal long-pause candidates (leading/trailing silence excluded), approximate WPM over the first-to-last VAD speech span and articulation WPM over detected speech duration. Rates require valid nonoverlapping segment times covering at least 80% of VAD speech; otherwise `NOT_ASSESSED`/null. Word counts come from the snapshot and are explicitly approximate, not forced alignment.
- Supported with uncertainty: repeated-word, filler and self-correction-cue candidates quoted from transcript segments containing detected speech, with segment-level timing. Such cues may be natural emphasis, discourse markers or useful self-repair, not mistakes. Pause IDs anchor adjacent transcript segments while their timestamps identify the actual audio gap. Every finding carries actual interval bounds, evidence, uncertainty, explanation and targeted practice; confidence is null because the detector does not expose a calibrated finding confidence.
- NOT_ASSESSED locally: phoneme/word alignment, pronunciation errors, accent correctness, pronunciation confidence and diarization. No ASR confidence is converted into a pronunciation score. No pronunciation error or targeted sound exercise is invented. Whole-recording metrics cannot distinguish the student from background speakers; noise, low-volume speech, music and incomplete transcripts can affect measurements. No band score or clinically/officially calibrated fluency judgment is claimed.
- Research (2026-10-31): [Silero VAD](https://github.com/snakers4/silero-vad) is maintained, lightweight and ONNX-compatible; its VAD is already installed through faster-whisper. [WhisperX](https://github.com/m-bain/whisperX) offers word/phoneme alignment, with additional model/dependency requirements; alignment alone does not establish pronunciation correctness, so it was not installed or presented as a scorer. [Azure pronunciation assessment](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment) uses a dedicated assessment model distinct from ordinary ASR; it requires separately configured service access and has not been integrated. No validated local pronunciation assessment model or such service credentials are available in the inspected environment.

#### AI speaking text feedback service

- Implemented `app.speaking_text:create_evaluator` as a configurable text-only chat-completions adapter. Set `SPEAKING_TEXT_PROVIDER=app.speaking_text:create_evaluator`, `SPEAKING_LLM_URL` (complete chat-completions endpoint), `SPEAKING_LLM_MODEL` and, where needed, `SPEAKING_LLM_API_KEY` in the backend/worker environment. Optional `SPEAKING_LLM_PROMPT`, `SPEAKING_LLM_TEMPERATURE`, and `SPEAKING_LLM_CHUNK_CHARS` configure instructions, sampling and chunk size. A replacement prompt must preserve the structured output contract and assessment safeguards.
- Each request sends transcript text and optional question/part; no audio or video is sent. Chunks contain at most 16,000 characters and 40 segments, with up to 256 characters of prior context. Oversized segments are split. Validated issues retain category, mistake-versus-improvement, exact original quote, correction, bilingual explanations, severity, confidence and suggested practice. Segment times are copied from the immutable snapshot, in milliseconds and as seconds in API response fields. Model-provided quotes must occur verbatim within the submitted chunk.
- Revision `003_text_feedback` adds nullable feedback fields and a PostgreSQL cache. Cache keys include prompt, endpoint, model, temperature, question, part, segment IDs and chunk text. PostgreSQL advisory locks coalesce concurrent identical requests. Cached responses are removed when their recording is deleted. Chunk requests carry a deterministic idempotency key; after ambiguous network failures, avoidance of duplicate provider-side processing depends on the provider honoring that key.
- HTTP 429/5xx and connection/timeouts retry up to three attempts; invalid JSON, invalid schema and invalid evidence fail visibly. No audio/pronunciation evaluator or score is implemented here. LLM feedback remains unofficial practice guidance; meaning preservation and linguistic correctness depend on the configured provider, despite exact-quote validation.
